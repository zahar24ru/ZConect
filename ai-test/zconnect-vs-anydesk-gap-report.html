Zconnect vs AnyDesk — Gap Report

Отдельный отчёт: чего не хватает Zconnect, чтобы приблизиться к уровню конкуренции с AnyDesk.

Короткий вывод

Zconnect уже выглядит как живой технический продукт, а не как просто прототип. У проекта есть клиент, сервер, signaling, ICE, удалённый экран, ввод, clipboard, file transfer, UI, лендинг и документация. Это сильная база.

Но до конкуренции с AnyDesk не хватает не одной-двух фич, а слоя зрелости продукта: стабильности, безопасности, polished UX, unattended access, релизного контура и доверия.

Что у Zconnect уже есть

  • удалённый экран;
  • мышь и клавиатура;
  • clipboard;
  • file transfer;
  • session model;
  • signaling server;
  • ICE / WebRTC transport;
  • собственный UI-клиент;
  • GitHub + Habr + landing page.

То есть проект уже не на нулевой стадии. Разрыв с AnyDesk сейчас в качестве, стабильности и зрелости, а не в полном отсутствии продукта.

1. Главный разрыв: стабильность и предсказуемость runtime

AnyDesk выигрывает не только набором фич. Он выигрывает тем, что:

  • почти всегда соединяется;
  • редко ломается странным образом;
  • предсказуемо восстанавливается после сбоев;
  • у пользователя нет ощущения, что он попал в хрупкую систему.

Для Zconnect это значит:

  • меньше гонок в reconnect/reset;
  • более чёткая state machine;
  • меньше временной/таймерной «магии»;
  • лучшее разделение transport / UI / session states.

2. Не хватает боевой security-модели

Для настоящей конкуренции с AnyDesk нужна не просто работоспособность, а доверие к модели доступа.

Сейчас в проекте ещё есть слабые места:

  • refresh/close сессии завязаны на session_id;
  • ws/auth trust model ещё не выглядит зрелой;
  • dangerous file operations требуют более строгой политики;
  • unattended access ещё не выглядит как законченный безопасный сценарий.

3. Не хватает нормального unattended access уровня “боевой продукт”

Для конкуренции с AnyDesk это один из ключевых пунктов.

Нужны:

  • устойчивый unattended mode;
  • machine identity;
  • долгоживущая trust-модель;
  • привязка устройства;
  • понятное управление доступом.

Если этого нет, продукт остаётся скорее инструментом для поддержки по коду, а не полной альтернативой.

4. Не хватает polished UX-простоты

У AnyDesk обычный пользователь быстро понимает:

  • что делать;
  • какой код передать;
  • что сейчас происходит;
  • как скачать / установить / запустить.

Zconnect уже идёт в эту сторону, но ещё нужны:

  • более чистые главные экраны host/viewer;
  • лучшие connection statuses;
  • меньше технических состояний в UI;
  • лучший onboarding для новичка.

5. Не хватает release/distribution зрелости

AnyDesk — это ещё и продукт, который легко:

  • скачать;
  • установить;
  • обновить;
  • запустить как сервис.

Zconnect для серьёзной конкуренции нужны:

  • installer;
  • release pipeline;
  • подписанные сборки;
  • понятная страница скачивания;
  • версионирование и changelog.

6. Не хватает инфраструктурной зрелости

У AnyDesk сила не только в клиенте. Там есть ещё:

  • экосистема устройств;
  • управление доступом;
  • корпоративные сценарии;
  • инфраструктурная предсказуемость.

Zconnect пока ближе к сильному техническому инструменту, чем к зрелой продуктовой платформе.

7. Не хватает differentiated positioning

Пытаться быть просто “ещё одним AnyDesk” — тяжёлый путь.

У Zconnect больше шансов, если у него будет понятная сильная позиция. Например:

  • простая open-source альтернатива для Windows;
  • удалённая помощь по кодам без перегруженного интерфейса;
  • self-hosted/контролируемая альтернатива;
  • локальный/русскоязычный продукт с понятной архитектурой.

8. Технически у Zconnect уже сильная база

Это важно отдельно отметить: проект не выглядит слабым. Наоборот, его фундамент уже лучше, чем у многих MVP.

Проблема не в том, что у него нет ядра. Проблема в том, что ядро ещё не доведено до уровня боевого продукта.

Итог

До конкуренции с AnyDesk Zconnect не хватает не столько набора фич, сколько уровня зрелости. Это хорошая новость: значит, у проекта уже есть ядро. Дальше вопрос в том, чтобы сделать его стабильным, безопасным, простым и достаточно polished, чтобы пользователь доверял ему как продукту, а не только как интересному техпроекту.
